# /push2github

Push the current project to GitHub safely. Run all four steps below in order, stopping immediately if any step fails.

---

## Step 1 — Secret scan (MUST pass before any push)

Scan every file that will be committed for sensitive data. Flag and STOP if any of the following are found:

**Patterns to detect:**
- Real email addresses in FormSubmit endpoints — the placeholder `your-email@example.com` is safe; any other address in a `formsubmit.co` URL is a secret and must not be pushed
- Tokens matching `ghp_`, `github_pat_`, `gho_`, `ghs_`, `sk-`, `Bearer `, `api_key`, `apikey`, `API_KEY`
- Strings matching `-----BEGIN * PRIVATE KEY-----`
- Passwords in connection strings (`password=`, `passwd=`, `pwd=`)
- Any `.env` file or file named `secrets.*`, `credentials.*`, `*.pem`, `*.key`

If any are found: show exactly which file and line, explain the risk, and ask the user whether to remove the secret or abort the push. Do NOT proceed until resolved.

If clean: confirm "✅ Secret scan passed — no sensitive data detected."

---

## Step 2 — Update README.md

Rewrite `README.md` to reflect the current state of the project. The README must include:

1. **Project title and one-line description**
2. **Live site URL** — read the GitHub Pages URL from the existing README or git remote; format as a clickable markdown link
3. **Features** — bullet list derived from the actual sections in `index.html`
4. **Tech stack** — table with Layer / Choice columns
5. **File overview** — short table of every file in the repo root (exclude `.claude/`, `.git/`, `push-output.txt`, `push-to-github.bat`)
6. **Local development** — how to run the site locally
7. **Form setup** — instructions for activating FormSubmit (mention the two files and lines to edit)
8. **Colour palette** — read the actual values from `:root` in `styles.css` and list primary, accent, background

After writing, confirm the file has been updated.

---

## Step 3 — Commit and push to GitHub

Find git using this priority order:
1. `git` on PATH
2. `C:\Users\Chelsea\AppData\Local\Programs\Git\bin\git.exe`
3. `C:\Program Files\Git\bin\git.exe`

Then run:

```
git add .
git commit -m "<auto-generated message describing what changed>"
git push origin main
```

Generate the commit message automatically by summarising the actual changes (`git diff --cached --stat`). Examples:
- `"Update hero section copy and pink accent colours"`
- `"Add beacon SVG logo to nav and footer"`
- `"Update README and repo About"`

If the working tree is clean (nothing to commit), skip the commit and say "✅ Nothing to commit — repo already up to date."

---

## Step 4 — Update GitHub repo About

Read the stored GitHub OAuth token from Windows Credential Manager (target: `git:https://github.com`) using the CredMan P/Invoke pattern already used in this project. Then call:

```
PATCH https://api.github.com/repos/{owner}/{repo}
{
  "description": "<one-line summary of the project>",
  "homepage": "<GitHub Pages URL>"
}
```

Derive `owner` and `repo` from `git remote get-url origin`.
Generate the description from the project title and tech stack (max 120 characters).
The homepage must be the GitHub Pages URL (`https://{owner}.github.io/{repo}/`).

Confirm: "✅ Repo About updated — description and live link set."
